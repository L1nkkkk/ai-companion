# ADR16：Unity 2022.3 / Cubism R4_1 回退路线与迁移验证

日期：2026-09-20。状态：**U01-00 基础工程验收通过，版本与 C# 协作边界已冻结。** 决策者：A0。范围：U01 Windows 原型基础工程，完整 UA02 与 U-G0 尚未通过。

冻结更新：被测源码 `849c6c982d875f477d88933af4abea5a163d0fa6` 已完成同机干净目录导入/构建及 600 秒 Player。依据 [A0 第三轮验收](../reports/U01/acceptance/PR-003-round3-review.md)放行 U01-01 至 U01-04；共享边界与 Transport→Audio 注入见 [CSHARP-BASELINE](../tasks/U01/CSHARP-BASELINE.md)。以下保留选型理由、迁移门槛与未来升级约束；内存/遮罩/取景等剩余项不因版本冻结而关闭。

## 触发与当前结论

U01-00 原候选为 Unity `6000.3.11f1`、Cubism `5-r.5`、URP。目标 Editor 官方下载在当前网络重定向后返回 404，尚无实际 Unity 编译与 Player；见 [PR #3 第二轮复核](../reports/U01/acceptance/PR-003-round2-review.md)。开发会话进一步报告官方独立 Unity CLI 及 `6000.0.71f1` 安装路径同样失败。本 ADR 引用该后续环境报告，不声称 A0 重新执行了安装。

用户已在开发任务“搭建 Unity 工程并验证构建”明确表示“我没有，或者换版本也行？”，授权评估版本替代。原 U01-00 owner 已完成独立实验，真实构建并运行 30 秒。A0 查看画面并核对包与证据哈希后，接受进入正式迁移，无需重复请求版本替换授权；正式工程版本冻结仍依赖下文验收。

**选择 Unity `2022.3.62f3c1` / `1623fc0bbb97` + 官方 Cubism `5-r.4.1` / 同包 Core `5.1.0` + Built-in Render Pipeline（BiRP），作为 U01-00 下一步唯一实现候选。** 目标为 Windows x64、Mono、D3D11。原 owner 可在正式开发分支迁移版本、渲染配置、资源清单和构建工具；保留原 R5 提交与实验快照以便审阅/回退，不并行维护两条产品主线。R5 下载失败不再是当前任务的必经阻塞；下载尝试可停止。

本 ADR 仅对 ADR15、U01 初始派工以及历史复核中“继续取得 Unity 6、不能以 2022 代替”的版本选择要求增加上述例外。Unity/C# 客户端、A0 仅设计与验收、临时协议与原有产品范围继续有效。U01-00-R1、U01-00-R2 保持关闭。

## 候选与已知差异

| 项目 | 原候选 | 独立实验候选 / 判定边界 |
|---|---|---|
| Editor | `6000.3.11f1`，下载受阻 | 本机 `2022.3.62f3c1`。R4_1 官方 README 列出 `2022.3.61f1`；本机不同补丁及 `c1` 构建以本项目干净构建/600 秒证据支持，不冒充官方同版或其他机器验证 |
| SDK / Core | 完整 `5-r.5` 包 | 官方完整 `5-r.4.1` 包及 Core `5.1.0`，成套使用 Wrapper、Framework、Shader。记录实际导入排除项与重序列化差异，重新登记哈希，不能继承 R5 清单 |
| 渲染 | R5 / URP | R4_1 / BiRP。独立工程清理不适用的 Unity 6 模块和 R5 渲染配置，登记实际解析成功的包版本，不混搭两代资源 |
| 模型 | R5 包中的 Mao | 优先 R4_1 同包 Mao；模型、纹理、动作和 `.meta` 重新核验。包内同名模型不自动视为相同资产 |
| 新模型特性 | R5 的 Cubism 5.3 新渲染能力 | 本候选不承诺高级混合、离屏绘制等 R5 新能力。后续自定义模型必须按能力清单选择，不能直接沿用 R5 兼容声明 |
| 遮罩与排序 | R5 的高精度遮罩与新绘制方式 | R4_1 使用不同遮罩和排序机制；要检查边缘、透明部位、正反遮罩与遮挡顺序，不能继承 R5 的截图或参数结论 |
| 业务边界 | 云端 AI、真实音频口型、UI/Session/Avatar 分层 | 保持；SDK 类型与渲染细节留在 Avatar/集成层，UI、服务协议和音频边界不随 SDK 改写 |
| 多机 / 手机 | 尚未证明 | 记录相同 Editor 与构建模块的获取步骤。当前机器成功不等于第二台机器或 Mac 可复现，更不等于 Android/iOS、后台音频或灵动岛已验证 |

技术依据：[R4_1 固定提交 README](https://github.com/Live2D/CubismUnityComponents/blob/ca8babb42333a2e4407aa72a78a12d7268294455/README.md)、[正式 R5 README](https://github.com/Live2D/CubismUnityComponents/blob/5-r.5/README.md)、[官方渲染差异说明](https://docs.live2d.com/en/cubism-sdk-manual/differences-from-before-unity-r4_1/)。差异说明仍使用 R5 beta 3 名称；本决策以正式 R5 README 交叉核对管线要求，不选 beta 包。[来源登记](../tasks/U01/SOURCES.md)区分文档依据与运行证据。

## 实验与 UA01 / UA02 的对应

实验交付记录在独立 `docs/reports/U01/U01-00/fallback-r41/` 下，并明确被测源码 SHA、设计起点、报告提交与原候选的差异。体积较大资源按现有分发规则提供位置和 SHA-256，不提交构建缓存。开发 owner 提交实现和实测；A0 只审阅与复核已有产物。

| 对应项 | 本组合所需证据 | 不能据此推导的结论 |
|---|---|---|
| UA01：版本与来源 | 精确 Editor、目标 Windows x64、脚本后端、图形 API、包清单/锁文件；官方 SDK 原包、Core、模型、字体及条件/哈希；实际导入和 C# 编译日志 | 已装 Editor、HTTP 200、原生 Core 单独调用或普通 Foundation CI 成功，都不证明 Unity 构建 |
| UA01：复现与产物 | 从登记的干净源码提交在新目录导入构建；完整 Player ZIP、包与可执行文件哈希、构建日志和运行方法；声明实际机器及获取条件 | 使用已有 Library/缓存的构建不能代替干净工作目录复现；本机复现不冒充第二台机器验证 |
| UA02：真实呈现 | 启动该构建的 Windows Player，提供实际画面/日志，核查材质、纹理、透明边缘、遮罩及排序；记录模型能力与参数/动作映射，分别检查眨眼、呼吸、视线、招呼的可用基础 | 参数存在、单张截图或短时启动不证明完整动画、交互、性能或稳定性 |
| UA02：时间与行为 | 按原验收表记录 10 分钟运行、异常与帧时间，逐项标明已实测行为；缺参数有明确降级。后续角色任务完成剩余呈现行为并复验 | 短时实验可证明候选值得继续，但不能将完整 UA02 或 U-G0 标成通过 |
| UA03 / UA04 及以后 | 保持原任务分工与验收标准；SDK 更换后，真实输出音量驱动口型、中文 IME、DPI、停止、云端和录音仍逐项实测 | 模型口部能动不代表实际声音驱动；Windows Player 能启动不代表完整陪伴体验 |

验收仍使用 [UA01–UA12 原表](../tasks/U01/ACCEPTANCE.md)。证据按子项记录已测与未测，禁止以 `spike_passed` 代替完整 UA 状态。测试时使用已修复的外部限时 Player 检查；若工具随实验改变，需报告差异并针对相关行为复核，不能把已关闭缺陷无理由重新打开。

## 从实验到正式采用

1. **已完成候选初评。** A0 接受独立实验的基础渲染可行性，允许原 owner 继续 U01-00 的正式工程迁移。实验源码包仍是本地快照，没有可作为验收起点的 Git 提交；不把原 PR 的 R5 提交标成已构建。
2. **开发 owner 迁移并提交。** 在原 U01-00 分支更新 Unity/包锁、渲染配置、SDK/Core/模型清单与工具；记录和原候选的差异，保留已关闭 R1/R2 的行为。提交精确源码 SHA 后，在新目录按资源说明完整导入和构建，核验 C# 边界编译、许可/模块、资源与产物身份；不得从实验 Library 复制缓存冒充复现。更新 PR #3 标题/描述和交接材料，明确选型已经改变。
3. **正式包验证。** 使用外部限时工具运行至少 600 秒，检查日志、完整画面、遮罩/排序与帧数据，报告眨眼、呼吸、视线、招呼与动作过渡的已测/未测范围。UA01 与 UA02 对应基础工程子项需真实证据；完整角色行为的剩余实现仍归 U01-01，不为通过 U01-00 改小完整 UA02 标准。
4. **A0 冻结与放行。** 已按第三轮验收完成 U01-00 范围复核，记录版本冻结、C# 共享边界与可派发起点，放行 U01-01 至 U01-04。完整 UA02 的剩余项继续按原任务归属验收；本次没有执行 PR 合并或宣告 U-G0 通过。

当前台账：U01-00 `complete`，版本 `accepted_foundation`，UA01 通过、UA02 基础子项接受，完整 UA02 未通过；U01-01 至 U01-04 为 `ready`，尚未因本文自动启动。原 R5 下载问题保留为历史候选缺口。

证据与迁移结论见 [A0 可行性初评](../reports/U01/acceptance/R4_1-initial-assessment.md)：第 04 次构建及最终运行、201 个构建文件、两份 ZIP 与源码快照的核验。短时结果支持迁移，不替代正式工程验收。

## 未来升级与回退

未来取得可用 Unity 6 环境或模型确需 R5 新特性时，再单独验证升级。升级成本包括 SDK/Core 成套替换、模型重新导入、材质与 Shader、相机/管线资源、遮罩与排序、包版本及构建工具；角色动画、实际声音口型、UI 输入和桌面性能需要相关回归。迁移范围是工程判断，不能承诺直接替换版本号即可。

若此次采用成功，保留可复现的 R4_1 源码与资源清单作为升级回退点；升级在另一分支验证，通过后再更新所有开发起点。若本次实验失败，原 R5 候选和已关闭 R1/R2 的审阅结果仍保留。正式 R1 契约、移动和直播的需求与验收目标不因本 ADR 改变。
