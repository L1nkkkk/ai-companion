# ADR15：Unity 客户端与设计、开发、验收分离

日期：2026-09-20。状态：接受。决策依据：用户明确要求 Unity，并明确本会话只负责设计和验收；随后授权编写任务书并同步 GitHub。

## 决定

1. 正式客户端采用 Unity / C#，角色使用官方 Cubism SDK for Unity。先交付 Windows 桌面原型，采用真实、可合法使用的 Live2D 演示模型。Android / iOS 前台客户端按 Unity 方向保留规划，Mac 与手机验证后移。
2. Python / FastAPI 继续承载云端模型与语音适配器。客户端不保存服务商密钥。未来手机后台音频、网络续期和系统入口仍由 Swift / Kotlin 原生模块负责，不假定 Unity 主循环能维持手机后台执行。
3. A0 所在设计会话仅负责设计文档、契约设计、任务拆解、评审与验收。允许运行只读检查和验收已有产物，允许提交设计文件。工程创建、SDK 导入、业务代码、构建配置、修复与打包，交给独立开发会话。A0 发现缺陷时派回 owner，不在本会话代写实现。
4. 用户决定是否启动新的开发会话。准备派工提示不等于已经派工；本次不创建开发会话、不启动实现、不安装 Unity 或 SDK。

## 当前成果与分支

历史 [P01 草稿 PR #1](https://github.com/L1nkkkk/ai-companion/pull/1) 保留为界面与行为参考。它是 React / SVG 演示，不是 Unity 或 Live2D 交付，不是新任务的强制依赖。其服务端代码可由新开发 owner 评估后选择性复用；不整体合并网页实现来充当 Unity 起点。

本决策和 U01 文档分支从 `origin/main` 的 `0bfc133` 创建，仅包含设计与协作文件。U01 开发从包含 ADR15 的文档提交开始；文档尚未合入 main 时使用 `design/unity-desktop-taskbook` 的指定提交，不能假定旧 main 已包含这些决定。

## 对旧设计的覆盖

ADR04 的 React / React Native 客户端路线、ADR05 的 Web viewer / WebView 容器路线，以及 P01 中把 React 作为后续客户端主线的安排，由本 ADR 覆盖。旧目录和历史报告保留，作为已发生的工程事实；不得据此继续扩大旧客户端。

R1 的需求、账号权限、设备租约、turn / epoch 隔离、音频与控制分离、手机后台及直播验收目标保留。`contracts/` 和已冻结的 `CONTRACTS.md` 未改动；其 renderer 桥接方法作为语义边界，具体 C# / 原生绑定需在后续任务中提交映射设计。

U01 是独立的本机开发预览，使用 [U01 接口草案](../tasks/U01/INTERFACES.md) 明确定义的临时协议，不声称实现 R1 `/v1` 认证、设备租约或实时二进制协议。正式协议迁移由 A0 单独审阅，不能让临时接口被手机或直播开发默认为正式服务。

旧 T09、T10、T11、T12、T13、T18、T19 的具体客户端实现卡需要按 Unity 重写后再派发；原业务目标和验收编号保留。U01 子任务已经在独立台账完整拆分，可以按门槛逐项领取。T00 未完成的真实第二机器验证、手机与直播资源缺口不会因文档更新自动通过。

## 技术核对与待验证项

官方提供 Cubism SDK for Unity；当前正式 R5 文档要求 URP，不支持把 Built-in / HDRP 配置直接混用。SDK、Core、模型各自记录来源与使用条件。Unity 6.3 LTS 为候选版本族，精确补丁、URP 与 SDK 包由 U01-00 通过导入和 Windows 构建后冻结。已有 Unity 2022.3 安装记录不作为兼容性结论。

后续选型以 [ADR16](0016-unity-2022-r41-fallback-validation.md) 为准：经独立实验，A0 选择 Unity `2022.3.62f3c1` + Cubism `5-r.4.1` + BiRP 进入正式工程迁移，基线仍待干净构建与验收后冻结；本 ADR 的客户端方向与 A0 职责保持有效。

证据与适用限制见 [U01 官方来源](../tasks/U01/SOURCES.md)。本次仅核对文档，尚未运行 Unity、取得模型包或证明本机 Unity 构建成功。
