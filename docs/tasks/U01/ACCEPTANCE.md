# U01 验收与证据清单

执行 QA：独立开发/测试会话。最终判定：A0 本会话。所有性能数值是目标，不是已测结果。

Unity 2022.3 / R4_1 / BiRP 回退实验按 [ADR16 的 UA01/UA02 映射](../../adr/0016-unity-2022-r41-fallback-validation.md)提供证据。下列标准保持有效；短时启动仅是实验结果，不能代替完整 UA02、U-G0 或 U01-00 的最终复核。报告必须区分基础工程已验证的子项与后续角色任务尚未实现的行为。

|---|---|---|---|

UA05 测量时分别报告“播放中停止”和尚未出声的取消，不把两组混合计算以降低 P95。用同一客户端单调时钟关联输入命令与最后非零输出音频块；采样方法必须说明操作系统输出缓冲的影响。具备 loopback 条件时记录真实输出尾音；仅日志声称调用了 Stop 不足以证明实际静音延迟。

首播性能至少采集 20 条真实云样本：提交文字或确认转写 → 第一个实际可听输出回调，分别列出 LLM、TTS、下载和播放耗时，报告 P50/P95、网络、文本长度与音色。U01 初始体验目标 P50≤5 秒、P95≤10 秒；不满足时登记体验缺陷和改进任务，不能宣传达到 R1 的更严格目标。该原型的阶段技术通过与首播体验目标单独列结论，不混为一项。

角色性能在登记的目标 Windows 机器上记录 10 分钟帧时间，目标 60 FPS；至少 95% 帧≤33.3 ms，无连续 1 秒 UI 阻塞。记录模型复杂度、窗口尺寸、显卡、内存峰值与增量。单个模型达标不能推广为任意 Live2D 模型达标。

## 2. 必须覆盖的竞争条件

1. 用户停止时，文字生成尚未完成；旧 provider 之后仍返回数据。
2. 文字完成、WAV 下载或解码尚未完成时停止；旧音频随后到达。
3. 语音正在播放时停止，马上提交新消息；两轮不得交叠。
4. 切换/删除会话后旧回调到达；不得写入新会话或复活已删记录。
5. 按住录音时失焦、拖出按钮区域或关闭窗口；必须释放麦克风，不依赖收到 key-up。
6. ASR 等待期间重新录音或编辑输入框；旧转写只在原请求仍有效且草稿未被后续操作替换时接受。
7. 取消先于后台接受到达；稍后 POST 同 request_id 不触发收费调用。
8. 生成完成事件先于播放器结束；不得提前显示“已经说完”。

并行 UI、音频、服务测试需使用同一固定样例集。重要失败附最小输入、时序、实际状态、预期状态和关联 ID；不得以增加 sleep、关闭测试或改小样本量作为修复。

## 3. 证据目录与格式

每个候选版本保存于 `docs/reports/U01/<gate>/`：

```text
report.md              本次结论、环境、命令、复现、限制
verification.json      每个 UA 编号的状态与证据位置
environment.json       OS/CPU/GPU/驱动/音频设备/Unity/SDK/模型/provider
build-manifest.json    source SHA、包 SHA-256、构建版本与产物位置
latency.csv            样本 ID、同一时钟耗时、取消位置、成功/失败原因
defects.md             失败项、责任 owner、修复提交、复测结果
```

录屏、原始构建日志和体积较大的测试输出使用测试分发附件，文档只存位置与哈希；只使用同意用于测试的样本。不要上传私人录音、云密钥、登录令牌或包含私人聊天的完整日志。原始麦克风音频不默认保留；需要保留测试录音时由提供者明确允许。

`verification.json` 每项使用 `passed / failed / not_run / awaiting_external`，记录 `tested_commit`、`tester`、`environment`、`method`、`evidence` 和限制。截图只证明画面；构建退出 0 只证明构建；Editor Play Mode 不替代 Windows Player；模拟 provider 不替代真实云端。

## 4. A0 在本会话的验收流程

1. 核对任务范围、提交、产物哈希、依赖与报告是否一致。
2. 阅读变更与测试，复现已有包的关键流程；不能执行时列出未验证项，不声称亲自运行通过。
3. 将缺陷分给对应开发 owner，并写明复现和通过条件；A0 不在当前会话补业务代码、改 SDK 或修场景。
4. 对修复版本重新核对相关证据和必要回归；确认旧证据对应哪些未变模块。
5. 按门槛分别给出通过、未通过或待外部条件。U-G0 可先给用户体验；U01 整体完成必须 U-G0/1/2 必测项通过、交付齐全，并完成 A0 审阅。

不得将 U01 的通过自动写成 T17、T18、R1 或 G1 全部通过。R1 的权限、租约、实时传输、移动与直播验收仍独立存在。
