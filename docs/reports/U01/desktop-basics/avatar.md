# U01-01 Mao 角色交接

本轮复用已接受的官方 Cubism 5-r.4.1 / Core 5.1.0 / Mao 资源。没有修改 SDK、模型源文件、依赖锁或共享 Contracts。运行时由 Composition 加载原 Mao prefab，Avatar 组件封装全部 SDK 类型与参数选择。

## 产品能力与范围

- 从真实模型枚举参数及上下限，发布能力清单；口型使用 ParamA，眨眼 ParamEyeLOpen/ParamEyeROpen，呼吸 ParamBreath，视线 ParamEyeBallX/Y。未知参数不写入。
- 每 2.8–5.3 秒自然眨眼，持续呼吸，鼠标进入角色画面时跟随视线；点击角色播放官方 mtn_02 招呼并恢复 mtn_01 idle。UI 弹窗与控件点击不触发招呼。无焦点时不跟踪桌面外光标。
- 只公开 Neutral 表情和 greeting 动作。原包 exp_01..08 没有冻结的情绪含义，不凭文件名猜测；其他情绪返回 Unsupported 与降级标记。
- 口型来自唯一 AudioSource 实际输出回调应用音量后的 RMS，乘以 4 并限制在 0..1。有声时平滑，静音样本、停止和旧操作失效立即归零；超过 250 ms 未收到有效采样也闭嘴。其他元音参数归零，防止原动作模拟说话。
- Avatar 在 Cubism 运动/物理之后、渲染更新之前写入参数。操作与 turn 身份必须匹配才能接受口型或表情，停止后的迟到事件无效。

## U01-F02 与 F03

U01-F02 未验证的五个特效 Drawable（ArtMesh274、273、256、193、192）明确排除本次产品能力，用 MeshRenderer.forceRenderingOff 持续关闭，不仅设置会被 SDK 覆盖的 enabled。没有把这些路径写成遮罩通过。special_01 等额外特效不进入产品动作集合。

U01-F03 使用专属角色视口及实际可见主体网格包络计算镜头，留出 22% 余量；全屏背景相机消除视口外横带，角色与音量/聊天控件分区。窗口变化重新计算取景。desktop-dev-04 实际 1280×800 Player 已目视确认完整帽子、身体、鞋和主要道具，角色明显大于首轮基于全部隐藏特效包络的错误取景。其他尺寸的最终复测见集成报告；不能将此推广为所有原包特效已验证。

## 证据边界

U01-F01 定位到发布动作的一处实际累积：官方 R4_1 动作层断开旧 playable 后没有销毁旧节点。对真实 SDK 的只读诊断及对照调用表明，连续 64 次直接播放会从 2 个增长到 130 个，`StopAllAnimation` 也不释放这些节点。Avatar 在招呼前经官方 OnDisable/OnEnable 路径重建动作图，再播放招呼并返回 idle；SDK 源码不改，FadeController 使用的层数组保持同一引用。64 次复位对照中旧图均失效，当前图最多 6 个节点，见 [探针结果](motion-graph-check.json) 与 [诊断源码](check-motion-graph.cs)。这项 Editor 诊断不代替实际 Player 长时运行。

最终 b94af81 Player 同步记录实际图节点、每五秒模型及三种内存指标、30 Hz 输出振幅、逐帧耗时和截图，完整结果见 [内存与帧时间报告](qa-memory.md)。前候选有截图/无截图的两轮用于定位，并行负载等干扰已保留，不能作为严格截图 A/B；当前固定动作集也不能证明原 Foundation 全动作增长的唯一原因已定位。招呼前重建图会重置原 idle 混合状态，这是当前仅发布 idle/greeting 的实现取舍，其他动作或混合方案需重新验证。

截图只证明画面，振幅回调不能单独证明系统声音；进程限定 WASAPI 测量另列方法和结果。第二机器复现（U01-F04）仍需外部设备与对应 owner，不由同机测试冒充。
