## 审阅方法与对象

证据由原 U01-00 开发会话在独立实验目录生成。A0 只读查看现有图片、结果 JSON、构建日志片段与清单，并独立计算文件哈希；未在本会话导入、编译、构建或重跑该 Player。

最初 `player-30s` 画面取景过小。开发方调整后，A0 查看 `player-framed-30s/player-03s.png` 与 `player-10s.png`：角色全身、帽子、刘海、眼睛、衣服、手臂和腿部清楚，两帧未见明显紫红缺失材质、大面积遮罩溢出或明显遮挡错误；中文说明可读。两帧姿态略有变化，但不证明完整眨眼、各表情与动作过渡、全部遮罩路径正确。

本次具体读取第 04 次构建结果 `import-build-04-result.json`（退出 0，用时 22.391 秒）及对应 `player-framed-30s` 输出。其运行清单时间为 `2026-09-20T09:26:38.7582073Z` 至 `09:27:12.5602447Z`；外部检查退出 0、未超时。A0 核验运行清单中全部 **201 个构建文件**的长度与 SHA-256，以及该目录 6 份证据的哈希，均一致。又核验两份 ZIP 哈希，并逐文件确认运行 ZIP 的 201 项与被测清单相同。

源码 ZIP 中，构建源码清单列出的 34 项实验脚本、设置与包配置长度/哈希均匹配；清单本身哈希也一致。此清单没有逐项列出全部 SDK/模型资产；源码 ZIP 的整体哈希限定当前归档，正式迁移仍须按资源获取清单核验完整导入。源码仍为本地快照，无 Git 提交，未执行干净目录重建，不能把它描述成原 PR 的 R5 提交已构建成功。

## 下一步与判定

本次独立实验已经结束，无需再等待实验产物或 Unity 6 下载。采纳理由是此组合已有实际构建与清晰图形输出，可支撑本阶段所需的基础模型呈现；R5 新渲染特性不在当前 U01 范围内，其迁移代价已在 ADR16 登记。

1. 原 owner 在正式 U01-00 分支统一迁移 Unity/SDK/Core/管线、实际包锁、模型与资源说明、构建工具。记录移除 Unity 6 模块、加入 uGUI、根响应文件省略与 asmdef unsafe、Editor 重序列化、R4 材质 API 和取景调整；保留 R1/R2 的已修复行为。
2. 提交精确源码 SHA，从新目录获取资源、导入、编译与构建。产物绑定该 SHA；补齐至少 600 秒运行及 UA02 基础呈现检查，逐项注明角色后续任务尚未实现的行为。
3. 更新 PR #3 与报告，交 A0 复核固定版本、产物和共享 C# 边界，再冻结 U01-00 协作起点、放行后续模块。A0 本会话继续只设计与验收。

完整 [UA01–UA12](../../../tasks/U01/ACCEPTANCE.md) 的目标保持有效。台账恢复 `in_progress`，含义是迁移工作已获准继续；并不代表整个 U01-00、U-G0 或移动兼容性通过。
