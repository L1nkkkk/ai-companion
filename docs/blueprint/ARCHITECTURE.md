# AI 虚拟角色总架构任务书

版本 1.0 · 2026 年 9 月 20 日

## 1 项目目标与责任

构建一个有统一人设、声音和 Live2D 形象的 AI 角色。用户在电脑或手机与她交流；主播在直播模式下让她选择并回应观众弹幕。Android 和 iOS 均提供可安装 App，用户开启陪伴会话后可在后台继续语音。iPhone 通过灵动岛或锁屏实时活动展示会话状态。

项目负责人决定产品优先级、角色审美、预算和对外发布。A0 主架构 agent 负责系统设计、接口冻结、任务分派、跨模块变更、集成顺序和最终技术验收。各开发 agent 对领取任务及对应测试负责。验收 agent 独立检查证据；A0 不以“所有 agent 都报告完成”替代集成验收。

本任务书里的“第一版”指全部 R1 需求完成；阶段演示只是其中一部分。软件开发与原画、模型绑定、配音风格设计分别推进。

### 2.1 R1 产品范围

以一个自用账号、一名主播、一个直播间为容量起点。个人会话与直播会话可同时存在，但只有显式指定的设备拥有各会话的输入和播放权。先使用现成模型及云服务提供的授权音色。提供基础账号登录、会话管理、聊天记录、可编辑记忆、音频控制、模型配置、弹幕队列和运行状态。

直播的“回应”默认通过角色声音和字幕进入 OBS 画面。向直播平台发送文字弹幕属于单独扩展，不包含在读弹幕权限中。

### 2.2 以后单独立项的能力

游戏自主操作、从零训练基础大模型、定制声音训练、全自动制作原画和 Cubism 绑定、多租户商业服务、付费系统、同时运营多个直播间、无须主动开启的全天候系统级唤醒、手机跨应用悬浮宠物，以及 App 商店公开上架运营。

“独立可安装 App”在 R1 中指可交付 Android 安装包和可通过签名测试渠道安装的 iOS 版本。公开上架需要另外的发布任务；iOS 真机验证依赖有效构建与签名环境。

## 3 核心体验

### 3.1 个人陪伴

用户打开 App 或网页，登录并选择角色，点击“开始陪伴”。设备完成麦克风授权并显示正在收音。用户说话，服务端生成回应，设备播放声音并同步字幕、表情和口型。用户可以插话、静音麦克风、停止当前回复或结束整个会话。

手机进入后台后，原生音频模块继续管理收音、网络连接、播放、令牌续期和停止操作；Live2D 暂停绘制。返回前台时从原生引擎和服务端恢复真实状态。静音必须停止向云端发送音频，结束会话必须关闭录音、播放和连接。

一期将“后台监听”实现为用户主动开启的持续陪伴会话。唤醒词和完全自动启动不作为 R1 前提。持续会话不保证在应用被用户强制终止、系统回收或权限撤销后继续运行；这些情况必须明确结束或提示恢复，不能仍显示“正在听”。

### 3.2 灵动岛与系统入口

灵动岛展示简化头像、听说状态和适合当前状态的快捷操作；完整 Live2D 在主界面呈现。实时活动不提供音频执行能力，也不等同于永久后台运行。苹果文档规定单次实时活动最长活跃 8 小时；活动结束与语音会话结束分别处理，禁止通过无限重建活动假装系统允许永久显示。[S01](SOURCES.md#s01)

iOS 原生音频采用适合双向语音的音频会话和后台音频能力。Android 从可见界面启动带麦克风类型的前台服务，并提供持续通知。具体操作的系统限制由 T01、T02 在目标系统版本验证。[S02](SOURCES.md#s02) [S03](SOURCES.md#s03)

### 3.3 直播互动

后台适配器接收平台事件，统一转换为弹幕输入。调度器完成去重、过期丢弃、频率限制和优先级排序。角色回应时，直播显示端负责音频、字幕和角色动作。控制台能暂停自动回应、选中一条弹幕、停止当前回复和结束直播会话。

默认先验证 B 站官方接入。最终平台取决于实际取得的开放能力。抖音作为第二适配器预留；已查到的官方接入类型存在不同权限、评论范围和部署条件，不能把一个类型的条件推及所有接口。[S08](SOURCES.md#s08) [S09](SOURCES.md#s09)

所有客户端都通过同一套受认证的服务端接口访问 AI 和数据。模型素材本地绘制，云端传送语音及控制数据，不传送连续角色视频。

### 4.1 技术选型基线

| 层次 | 默认选型 | 选择目的 |
|---|---|---|
| 网页与直播界面 | React、TypeScript、Vite | 复用角色和控制界面 |
| 手机界面 | React Native，保留完整 iOS 和 Android 原生工程 | 共享界面，允许开发系统能力 |
| iOS 原生能力 | Swift、系统音频、ActivityKit、SwiftUI 扩展 | 后台语音与灵动岛 |
| Android 原生能力 | Kotlin、音频处理、前台服务与通知 | 后台语音与系统控制 |
| Live2D 显示 | 官方 Cubism SDK for Web，封装为独立 viewer | 网页、OBS、手机前台复用 |
| 手机角色容器 | 原生 WebView 加载打包的 viewer 文件 | 与原生音频通过窄接口通信 |
| 服务端 | Python 3.12、FastAPI、asyncio | 流式 AI 调用与会话调度 |
| 数据库 | PostgreSQL、版本化数据库迁移 | 会话、记忆、设备与持久化元数据 |
| 实时连接 | 分离的控制 WSS 和音频 WSS | 控制消息不排在大块音频之后 |
| 开发与发布 | GitHub 私有仓库、worktree、持续集成 | 多机器与多 agent 协作 |

React Native 支持连接 Swift、Kotlin 等原生模块，但共享界面并不自动获得原生后台能力。[S10](SOURCES.md#s10) 技术具体版本由 T00 选择稳定版本并写入锁文件，不追逐每个 agent 所在机器的最新版本。

首版后台使用模块化单体和一个会话运行进程。直播连接、AI 适配器和数据库访问均采用异步、限时调用。禁止直接启动多个独立 worker 共同管理同一会话；未来扩容需要加入共享会话所有权与消息路由，并另立决策记录。

### 4.2 WebView 的责任边界

WebView 只负责前台 Live2D 绘制和触摸事件。收音、播放、音频网络、后台令牌续期、重连、静音与结束控制全部在手机原生引擎中执行。JavaScript 或 WebView 暂停后，音频不能因此失去生命周期管理。

先在 WKWebView 和 Android WebView 真机验证 Cubism。官方浏览器平台支持可作为选型依据，但不能代替嵌入 WebView 的兼容性测试。[S05](SOURCES.md#s05) 如果目标机型不可用，由 A0 评估原生 Live2D 渲染替代，其他接口保持不变。

## 6 实时语音设计

### 6.1 从收音到回复

原生端或网页端采集音频，完成回声处理和语音活动检测。仅在会话开启、麦克风未静音且持有输入租约时发送音频。保留短暂起音缓冲，避免丢失第一个字；语音段结束后提交最终识别。客户端检测只决定何时采集与发送，服务端仍负责限制长度和决定是否接受输入。

服务端将最终识别作为用户输入，为新回复分配 turn_id。云端对话内容逐步到达后，按完整短句形成不可再修改的语音片段，随后合成并播放。展示中的临时文字与已播文字分开记录。中断后不能把尚未播放的整篇回复记录为“她已经说过”。

R1 传输约定是单声道 PCM16LE，输入标准采样率 16 kHz，输出标准采样率 24 kHz，100 ms 为正常发送块。设备录音硬件或 provider 使用其他采样率时，由对应适配层重采样。格式及分帧详见接口契约。弱网实测不达标时，A0 可通过决策记录改用 Opus 或 WebRTC；其他 agent 不得各自更换协议。

### 6.2 取消与插话

用户点击停止时，播放端先立即清空本地待播音频，再发送取消。服务端标记该 turn 为终止，取消识别后的生成与合成任务，并丢弃供应商迟到的数据。所有播放、字幕和动作均携带 turn_id 和会话代次；旧代次与已取消 turn 的数据必须丢弃。

自动插话依赖回声消除和语音检测，不能让角色自己的扬声器输出再次触发识别。回声效果不可靠的设备必须提供按住说话或耳机模式。直播弹幕通常等待当前句子结束；主播显式停止操作具有最高优先级。

### 6.3 声音与角色一致

口型使用实际播放到扬声器的音频振幅计算，不能以服务端发送速度驱动。情绪和动作在对应语音片段开始播放时生效。默认动作集合为 neutral、happy、sad、surprised、thinking 和点头等有限映射；不支持的动作降级到中性状态。模型能力清单决定真正可用的动作，不能要求不存在的参数。

灵动岛只呈现少量语义状态，例如“正在听”“思考中”“正在说话”“已暂停”。音频振幅不逐帧推送到实时活动。完整角色状态由前台 viewer 在恢复时同步。

### 6.4 手机后台

原生模块拥有独立状态机：inactive、starting、listening、thinking、speaking、muted、interrupted、reconnecting、ended。界面只订阅它。控制服务中断时停止发送新的云请求，保留可恢复信息，并在连接恢复后取得新代次和状态快照。

收到来电、系统音频中断、麦克风权限撤销、蓝牙断开或服务终止时，由原生状态机处理。耳机拔出后的默认策略为暂停播放，避免突然外放。应用被强制关闭后，下次启动提示恢复先前会话，不承诺自动重新收音。

## 7 会话与直播调度

每个 session 指定 owner_id、character_id、mode 和独立上下文。mode 为 personal 或 broadcast，创建后不可原地切换；切换模式建立新 session。一个 session 同时最多有一个被接受的活动回复 turn、一个输入设备和一个播放设备，其他设备是观察者或控制者。

同账号从电脑切到手机时，用户显式接管会话。服务端提升 session_epoch，撤销旧租约、取消旧 turn，并给新设备发送快照。旧设备停止收音和播放。OBS 默认是直播会话唯一播放端，控制台默认静音，避免重复声音。

直播队列默认最多 50 条、保留 30 秒。按平台事件 ID 去重，重复问题可合并。优先级顺序为：停止与静音控制、主播主动输入、主播选中的弹幕、普通弹幕、空闲主动发言。礼物感谢先合并，在平台能力验证后再启用。队列满时丢弃最旧的低优先级消息，并计数。

弹幕是观众输入，不能改变系统人设、会话权限或获取个人记忆。R1 的自动动作仅限角色表现，不执行任意代码、文件操作或外部账号操作。直播文本在进入语音队列前通过可配置内容规则；控制台始终保留一键停止自动回应和当前播放的能力。

## 8 数据与记忆

| 实体 | 主要字段 | 保存原则 |
|---|---|---|
| users | id、登录信息、设置 | R1 单账号，保留所有权字段 |
| devices | id、owner_id、平台、能力 | 每台设备独立凭据 |
| characters | id、版本、人设、音色、模型清单 | 文本配置版本化 |
| sessions | id、owner_id、character_id、mode、epoch、状态 | 个人与直播隔离 |
| turns | session_id、输入、回复片段、终态 | 记录中断与实际播放状态 |
| memories | owner_id、character_id、scope、内容、来源、确认状态 | 支持查改删 |
| live_connections | 平台、主播关联、权限状态 | 密钥在服务端秘密存储中 |
| usage_records | provider、会话、用量、时间、计费依据 | 不把估算标为实际账单 |

近期上下文由最近对话和会话摘要组成。长期记忆只保存用户显式要求记住或确认的事实；自动提取先作为候选。每条记忆有来源、时间、作用范围与删除标记。个人记忆不会进入直播上下文。上下文拼装层统一执行范围过滤，不能仅在 UI 隐藏。

文字历史保存到用户删除或配置的保留期限。广播上下文与原始弹幕默认只短期保留，建议 7 天；具体保留期由项目负责人在启动配置中确认。原始麦克风音频不默认持久化；合成音频使用短期缓冲。删除会话会删除相应记录及基于它生成的摘要；引用该来源的记忆应删除或移除来源后重新确认。备份保留与删除生效时限要写入部署说明。

## 9 身份与运行配置

R1 使用单拥有者账号，关闭公开注册。初始化通过一次性管理流程创建账号。网页使用安全会话 cookie；手机访问令牌与刷新凭据放在系统安全存储。具体 token 和连接票据见接口契约。

云服务密钥始终由服务端持有。OBS 使用可撤销、仅访问某一直播 session 的显示凭据；它不能访问个人历史、修改人设或发送普通控制命令。API 每次按用户、session 和角色权限授权，不以难猜的 UUID 代替授权。

本地 mock 模式不需要真实密钥。真实 provider 模式要求设置调用额度、并发限制、最长输入和超时；额度或密钥缺失时给出明确配置错误。正式开发时比较至少两个可访问的中文方案，按音质、首句延迟、打断能力、可用地域与实测用量决定，不在本任务书里虚构价格或效果。

## 10 部署与开发环境

开发仓库采用单仓库。各台开发机安装锁定版本，通过 GitHub 接力或独立 worktree 并行。运行数据不通过 Git 同步。多机代码协作和手机访问同一服务是两件分别配置的事情。

开发期可以在 Windows 本机运行服务端、网页和 Android 工具。移动跨网络测试及实际使用需要可访问的 HTTPS 服务。R1 推荐一个持续在线的服务实例加 PostgreSQL，并配置备份、错误日志和基础监控。数据库、服务端、资源目录分别持久化；进程重启后会话可以重新连接，但不自动重播已经说过的音频。

当前已确认的机器为 Windows 11、Core Ultra 7 265、约 64 GB 内存和 RTX 5060 8 GB，已有 Node.js、Python、Git、Unity 2022.3 等。移动工具链尚需专门准备。iOS 构建与调试需要 Mac 和 Xcode，本地或远程均可；还需可实际安装测试版本的签名条件。[S04](SOURCES.md#s04)

## 11 开发阶段与退出条件

| 阶段 | 结果 | 退出条件 |
|---|---|---|
| G0 可行性与契约 | 仓库、mock、手机音频和直播接入证据 | 两种手机原生路径可行；至少一平台具备真实接入路径；契约校验通过 |
| G1 桌面完整流程 | 文字与语音交互、Live2D、取消、记录 | 桌面语音闭环通过，旧音频不会在取消后继续播放 |
| G2 双端移动陪伴 | Android、iOS、后台音频和系统入口 | 两端真机各完成 60 分钟会话及中断恢复测试 |
| G3 直播与完整 R1 | 真弹幕、调度、OBS、多设备接管 | 真实直播演练、数据隔离和干净环境复现通过 |

G0 中的真实资源验证与 mock 上的开发可并行。任一真实验证缺失时，不能用模拟器、模拟弹幕或单机截图替代并宣布完整 R1 完成。若某个平台路径不可行，由 A0 提交明确的范围或技术变更供项目负责人决定。

## 12 性能与容量目标

这些是验收目标，不是当前测得的性能或供应商承诺。统一测试条件和统计方法见验收规范。

- 正常网络下，用户停止说话至听到首段回应，目标 P50 不超过 2.5 秒、P95 不超过 5 秒。
- 显式点击停止到本机静音，目标 P95 不超过 200 ms；不能等待云端取消成功。
- 桌面角色目标 60 FPS，移动前台目标 30 FPS；允许通过模型复杂度与画质档位调整。
- 两台目标手机分别完成 60 分钟后台会话；随后做 2 小时前后台混合测试并报告耗电、发热与断线次数。
- R1 负载按一个个人会话加一个直播会话测试。普通弹幕输入可达到每秒 20 条，语音仍按有界队列串行播出。
- 每一轮记录识别、生成、合成、首播和取消时间，以及 provider 用量；后台空闲不得不停发起新的 LLM 请求。

## 13 多 agent 协作

A0 先冻结共享契约，然后分派有明确目录归属的任务。每个任务在自己的分支或 worktree 完成。共享锁文件、根配置、数据库迁移序号、schema 和原生工程公共配置由 A0 协调，避免多个 agent 同时修改。

开发 agent 必须交付代码、相关测试、运行方法、结果证据、已知限制和接口变更清单。A0 集成后由 A8 运行跨端测试。每次合并只证明该任务通过，不自动证明整个阶段完成。

详细角色、任务清单、可复制派工提示和交接格式见 AGENT_PLAYBOOK 与 TASKS。本项目不要求在同一时间启动所有角色；可按机器和 agent 配额分批运行。
