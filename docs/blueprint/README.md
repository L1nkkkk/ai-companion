# AI 虚拟角色架构与协同开发任务书

版本 1.0 · 2026 年 9 月 20 日 · 设计负责人：主架构 agent A0

本交付包用于启动一个兼顾桌面语音聊天、直播弹幕互动以及 Android 和 iOS 随身陪伴的 AI 角色项目。AI 能力采用云端服务，角色采用 Live2D。iPhone 支持灵动岛或锁屏实时活动，手机在用户主动开启陪伴会话后支持后台语音。

这是可以交给多个开发 agent 执行的设计基线。当前已导入正式开发仓库，执行状态请看 [T00 交接](../reports/T00/README.md) 和 [仓库入口](../../README.md)。设计本身不代表手机后台能力、直播平台权限或云服务效果已经通过实测。

## 已确认的需求

- 桌面端支持中文语音聊天，角色有声音、口型和表情。
- 第一版完整交付需要包含一个直播平台的真实弹幕互动；B 站或抖音均可。
- Android 和 iOS 都要有独立安装的 App。
- 手机切换应用或锁屏后，希望能继续陪伴和监听；iPhone 希望能在灵动岛看到状态。
- 初期使用云端 AI，优先尽快得到可体验的效果。
- 多台机器开发，通过 GitHub 管理代码；未来由多个 agent 协作，由 A0 负责架构与集成。

## 本版设计默认值

以下是为了能开始开发而作出的架构决定，可通过决策记录调整：B 站优先验证；Python 模块化后台；React 网页；React Native 手机界面；Swift 和 Kotlin 分别负责原生音频及系统入口；先用现成的可合法使用的 Live2D 模型；一个自用账号、一名主播、一个直播间。

移动端最低系统版本、具体云服务商、音色、正式模型、服务器地域与预算、Mac 构建资源以及直播开发者权限，都列为启动阶段的确认项。它们不阻止阅读和拆解本任务书，但可能影响真机验证与发布。

## 第一批怎么安排

1. A0 完成 T00，建立正式仓库，导入本交付包，锁定工具版本和共享契约。
2. 在各自资源就绪后，分别安排 T01 iOS 后台音频验证、T02 Android 后台音频验证、T03 直播权限与弹幕验证。三项可以并行。
3. 使用 T04 的离线模拟服务推动其他模块，真实平台的验证继续独立进行。
4. 按 TASKS 中的依赖推进。未通过真实手机和直播验证的版本，可以称为开发预览，不能称为满足完整第一版需求。

## 本交付包的校验

在独立 Python 环境安装 tools/requirements-validation.txt，然后运行：

~~~text
python tools/validate_blueprint.py --root .
~~~

检查内容包括27种控制事件的正例、8个反例、25个REST操作及其定义引用、音频头格式、21个任务的依赖图、需求与验收映射和文档内部链接。它验证设计包的一致性，实际应用的性能和平台能力仍须按验收任务执行。

## 文档优先级与修改规则

用户最新明确指示 > 已接受的决策记录 > 总架构任务书 > 接口契约与机器可读 schema > 任务说明 > agent 自行假设。接口文档和 schema 出现矛盾时，停止相关接口实现，由 A0 统一修订，不能选择一份继续。对已冻结接口的任何改动必须连同 schema、示例、客户端和测试影响一起审阅。

本仓库已采用正式布局：contracts 和 tools 位于根目录，设计文档与 planning 位于 docs/blueprint；只保留一份权威契约。原始 ChatGPT 项目中的 sources 保持只读，正式代码在独立开发目录维护。
